## Limits retained for acceptance

- Carried forward from ESC-D, still accurate: Yahoo quote retrieval time is known but an upstream exchange observation timestamp is not supplied; filing venue is historical evidence, not independently verified current listing metadata; preferred-share zero remains a guarded inference; historical adjusted-price filtering does not certify adjustment vintages.
- **One remaining Momentum case (ESC-22):** an invalid bar dated on the boundary's own date but stamped after the boundary instant still fails an `--as-of` run. Yahoo's daily bars are stamped at midnight, so it cannot occur with them; it applies only to a provider that stamps a daily bar later in its date. Tested and noted in `MOMENTUM.md`.
- Live Momentum arithmetic is limited to about 1e-8 relative by provider noise in adjusted closes. Earlier in the window Yahoo returned non-finite prices for the 2026-09-30 row (about 00:00Z to 01:30Z on 2026-10-01); success-path evidence was taken once the data was valid, and the failure path was exercised identically on both revisions.
- FCF compares a fact's availability with the run's boundary exactly, including on a live run, while the Graham resolvers accept ten minutes of clock skew (ESC-21). Annual facts carry the filing's acceptance time, so no real run is affected.
- The Massive provider was exercised only to its configuration error: no key is configured. Forward-consensus policies depend on a consensus provider that is not configured.
- Graham Number produces a value live only for KO; AAPL and MSFT fail on both revisions on preferred-share evidence (ESC-17's guard).

These are documented evidence and capability limits, not deferred known repairs. Live checks do not certify
universal upstream data accuracy or the absence of all future defects.
